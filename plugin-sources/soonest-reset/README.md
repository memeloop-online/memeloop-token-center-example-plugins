# 额度管理

统一管理 Codex 账号的请求分配与临期手动重置次数。插件沿用 `mtc-soonest-reset`，已有组配置可直接升级。

## 额度分配

在“模型路由 → 路由组 → 组路由策略”中选择“按账号额度分配”，选择本组实际额度（如“Codex · 周额度”），保存即可。唯一额度自动选中。

- **按剩余额度分配新会话**：同一会话优先沿用账号；新会话结合剩余额度和历史请求量，优先分配给较空闲的账号。持续更新的上游剩余额度反映长短请求的实际用量。
- **优先使用即将重置的额度**：先使用额度更早重置的账号。

新配置默认使用比例分配。已有配置保留 `target_provider`、`target_window_id`，省略 `mode` 时继续使用即将重置排序。示例：

```json
{"target_provider":"openai-codex","target_window_id":"code:primary_window","mode":"remaining_balance"}
```

核心提供授权候选的额度快照、最近24个小时桶的请求统计、共享请求预占及会话首选。插件比较剩余额度目标份额与历史请求份额，为新会话生成完整候选排列；同一账号的多条路由共同参与一次计算。新会话通过共享版本校验预占，既有会话优先维持账号并尽力记录预占；计数争用由后台实际完成统计补齐。后台在同一快照同步已完成请求的实际账号统计并抵扣对应预占；下一轮会话读取成功回退的实际账号。额度进入新周期后，历史仅保留当前周期内的小时桶（包含边界小时）。token总量单独提供诊断；分配统计采用请求数，上游剩余额度反馈实际用量。额度读取和重置工作由后台执行。

## 临期重置

在“上游服务”中打开当前 Codex 账号，在已有重置设置中开启“在手动重置次数到期前 10 分钟自动使用”。系统在手动重置次数到期前十分钟自动使用一次。页面显示可用次数、到期时间、授权状态和最近结果。授权使用原有账号级 CAS 接口及后台执行记录。

## 运行与发布合同

单一组件同时导出 `memeloop:token-center/group-routing-v1@0.2.0` 和 `memeloop:background-actions/planner@0.1.0`。两个规划器都使用核心授权的快照，分别返回候选排列和重置意图。核心负责权限、有效期、幂等记录与实际执行。

能力声明为 `group_routing_quota` 和 `quota_reset_credit`；后台周期为60秒。1.2.0 需要支持 `operator.upstream-account.reset-settings` 的核心版本；先升级核心，再安装此插件。发布包含同版本组件、中英文界面与签名安装证据。真实 host CI覆盖组合组件加载、额度路由、临期重置与界面操作。
